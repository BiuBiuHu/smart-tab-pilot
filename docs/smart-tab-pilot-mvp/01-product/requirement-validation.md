## 2. 目标澄清

- 用户真正想完成的业务结果：打开已存在的同一 URL 时，**立刻跳到已有标签并关闭新标签**，避免重复开页；同时把多主题标签按**页面正文语义**收进 Chrome 标签组。
- 主要用户/角色：重度 Chrome 用户（研发、调研、多文档并行）
- 核心操作闭环：
  1. 打开/导航到 URL → 精确去重跳转（P0）
  2. 页面 load complete → 抽取正文 → 分类 → 进组（P0）
  3. （后续）快捷搜索打开中/最近关闭并跳转或重开（P1）
- 工作单元和批量范围：单标签事件为主；「立即分组当前窗口」为窗口级批量
- 成本、时延和质量约束：优先本机 Nano（可提示下载）；否则用户 OpenAI 兼容；否则启发式。抽取硬上限约 4000 字符，不用截图多模态
- 返工/重试/回滚粒度：关闭自动分组开关；手动「立即分组」；关闭去重开关。MVP **不**把用户手动改组作为学习信号
- 已向用户确认的结论：
  - 精确 URL 匹配才跳转（默认含 hash；可选忽略 hash）
  - 按正文语义分组（非域名）
  - Nano 优先，downloadable 提示 + 自备模型 + 启发式
  - 开源 MIT；参考 page-agent 文本 DOM，不 vendor 全栈
  - MVP 首要成功标准 = 精确去重跳转
  - 语义分组进 MVP；快速搜索 = P1 / 后续版本
  - 按 opc-skills manual-gated 研发
- 仍需反问用户的问题（不阻塞进 PRD，可在审核时勾选）：
  - 关闭记录是否坚持仅本机、不上云（默认是；当前实现为 storage.local + sessions）
  - Chrome Web Store 上架是否纳入本 feature 后续里程碑，还是长期仅 Load unpacked

## 5. 状态、权限和环境

- 状态机（功能开关）：`exactDedupeEnabled` / `autoSemanticGroupEnabled` / `ignoreHash`；Nano availability：`available|downloadable|downloading|unavailable|missing`
- 角色权限：单用户本机扩展；无账号体系
- 预发/线上差异：无后端；「预发」= 开发者 Load unpacked；「生产」= 可选 Chrome Web Store
- 数据来源：`chrome.tabs` / 页面 DOM 抽取 / 可选出站 chat completions
- 数据写入和副作用：`chrome.storage.sync`（设置与自定义 Key）、`chrome.storage.local`（最近关闭，P1 能力）、`chrome.tabGroups`、关闭重复标签

## 6. 边界、异常和成本保护

- 空态：无可分组 http(s) 标签；抽取失败时退化为标题/URL 启发式
- 错误态：受限页（chrome:// 等）跳过；CSP 注入失败走 executeScript 回退；自定义模型 HTTP 失败降级启发式
- 慢请求/超时：自动分组 debounce ~800ms；Service Worker 休眠后首次分类可能变慢（可接受）
- 重复提交：去重用 `closingTabIds` 防重入；去重关闭不写入最近关闭
- 并发/顺序：同窗口逐标签分组；窗口级「立即分组」串行抽取+分类
- AI/生成成本保护：优先 Nano；自定义模型 `max_tokens` 小；正文硬截断 4000；禁止截图多模态
- 缓存/对象存储复用：不适用（无 OSS）；标签级标签结果不强制持久化缓存（MVP）
- 最小返工粒度：单标签再次 load complete 或「立即分组」
